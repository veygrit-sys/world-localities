# 日本のデータバンドルと復元確認

日本を先行対象として、保存済みデータをオフラインでまとめ、別ディレクトリへ復元する共通処理を追加しました。国別配布の前に、実際のファイル・出典・利用条件・依存を一緒に扱えることを確認します。

## 今回まとめる範囲

- `registries/asia/country-archives/JP.zip` と、その版・メンバー・出典・利用条件の記録。
- `registries/official/JP/` の派生台帳、原典ZIP、原典記録、未解決行、README・利用条件。
- 公式日本台帳のローマ字省略保存を解釈する `registries/official/romanize.py` と、共通の利用説明。

これは出典を区別したデータスナップショットです。日本に関する全レイヤーや、稼働する検索・住所検証サービス一式を含むものではありません。実行環境や他の処理が必要な場合は、マニフェストの固定Gitコミットからコードを取得してください。

## 実行方法

リポジトリのルートから実行します。追加パッケージや外部通信は使用しません。出力先はリポジトリの外にある、未作成のファイル・ディレクトリを指定します。親ディレクトリは事前に用意してください。

```bash
python scripts/country_bundle.py build --country JP --output /tmp/JP-data.zip
python scripts/country_bundle.py verify --bundle /tmp/JP-data.zip
python scripts/country_bundle.py restore --bundle /tmp/JP-data.zip --output /tmp/JP-restored
```

`build` は現在のGitコミットをデータの版として固定します。過去の記録を再現する場合は、記録された `--source-commit` を指定します。元ファイルが指定コミットと違う場合は停止します。

## 検査する内容

| 段階 | 検査 |
|---|---|
| 元データ | 指定コミットのGit blob、既存のJPアーカイブと全メンバーハッシュ、日本郵便等の保存済み原典ハッシュ、ローマ字処理のコードハッシュ |
| 作成 | 固定時刻・並び順・権限を用いたZIPと、全ファイルのサイズ・SHA-256・Git blob SHA |
| バンドル | 未宣言・重複メンバー、パス逸脱、シンボリックリンク、特殊ファイル、過大サイズ、利用条件・依存ファイルの欠落 |
| 復元 | 全メンバーの検査が終わってから新しいディレクトリを作成し、元の配置を再現。既存出力は上書きしない |

同じ入力と同じPython・zlib環境での再作成を確認しています。圧縮ライブラリの版が異なる環境でもZIP自体が同じになるとは保証しません。復元したファイルのSHA-256はマニフェストで比較できます。

内部マニフェストのハッシュは破損検出に使います。提供元の真正性を確認する場合は、信頼できる経路から取得したバンドル全体のチェックサムと照合してください。

## 確認記録と公開状態

[JPの往復検証記録](../releases/countries/JP/bundle-verification.json) に、固定コミット、実際のバンドルのSHA-256、ファイル数、作成・復元の結果を記録しています。検証用ZIPは一時領域で作成し、Gitには保存していません。

実際の外部公開・アップロードは行っていません。国別台帳の `release_manifests` には実在する公開先を確定してから登録します。ここでの検証成功は、全国完全性・最新性・配達可能性・住所検証精度の向上を意味しません。原典ごとのNOTICEと利用条件を保持し、全体へ新しい一律ライセンスは付与しません。

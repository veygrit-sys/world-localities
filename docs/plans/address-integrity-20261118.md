# 住所検証・住所翻訳の更新方針

作成日：2026-11-18。対象：`veygrit-sys/world-localities`。
開始時点のmain：`a59ad41bca5ed2336dbc9923173f5dad303ce89d`。

## 今回の優先順位

国別データの追加に先立ち、全地域で再利用している住所形式・多言語選択・検証結果の共通処理を修正する。

| 優先 | 確認した問題 | 到達条件 |
|---|---|---|
| 1 | Address2があると構造化された階・部屋番号が消え、未表示項目にも出ない | 明示された詳細を表示へ保持し、併合と未表示を報告する |
| 2 | 郵便番号・番地などに言語別の異なる値を与えられる | 同一住所の識別値の矛盾を拒否し、入力原文を結果から参照できる |
| 3 | 検証レベルの型や配送根拠の検査が弱い | Python契約とJSON Schemaを揃え、不正な値・追跡不能な配送根拠を拒否する |

## 実装と受入

- 国別テンプレートを複製せず、`addressing/` の共通処理を更新する。
- 部屋番号の欠落、日英の郵便番号・番地矛盾、入力の変更による原文の消失、不正な検証レベル・根拠を回帰テストで再現する。
- Address2など不透明な文字列を再解析して、部屋番号や翻訳を推測しない。併記には一般的な表示順を使い、郵便事業者承認とは扱わない。
- Address1・受取人・州名の未表示追跡は、実際に代替項目へ反映した場合だけ省略する。既知の州名とコードが矛盾すれば警告し、州名が表示されなければ未表示項目にも残す。
- 中立値の同一性は正規化後の完全一致で保守的に判定する。書式差・異なる数字体系の同値判定は、別途国別ルールを設計してから追加する。
- 通常のオフライン回帰と階層テストを実施し、GitHubの作業ブランチとPRへ反映する。

## 次の工程

1. 未完了の国別PRを個別の出典・差分・CIで確認する。今回の共通修正へ無条件に混ぜない。
2. 中国本土を先行してAlibaba Cloudと自作処理の比較に使う共通入出力・評価例を固定する。原文・国・言語・データ版・確認範囲を保持する。
3. 国内の住所記載で実際に使われる言語を標準フォームの対象として整理する。既存の互換表記と標準フォームの提供言語を分け、インドの標準フォームは英語とする。少数言語専用フォーム・翻訳を今回追加しない。正式な地名・街路名の原文は保持する。
4. 外部で独立確認した評価例で誤受理・保留・正解率を測る。合成回帰テストを実住所の精度実績に数えない。

今回はライブ住所APIの接続、機械翻訳モデルの学習、国別原典の再取得、全国完全性・配達可能性の実証は行わない。配送根拠の参照が存在するという契約検査は、外部証拠の真正性の検証ではない。

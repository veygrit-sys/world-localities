# 住所 AI の受入試験と本番判定

このディレクトリは、住所検証・入力補助・表記変換・送り状の住所欄をまたぐ回帰試験用。実在の自治体名・郵便番号に架空の通り名・建物名・部屋番号を組み合わせている。顧客住所、配送結果、学習用データを含まない。

```sh
python -m unittest discover -s tests -p 'test_address_ai_acceptance.py' -v
```

[ケース](acceptance-cases.json)の候補索引は、一時ディレクトリにテスト実行時だけ構築する。検索やラベルの判定処理自体は置き換えない。加えて、米国ワシントンDCの公開施設（ホワイトハウス、DC MAR `293211`）を一件だけ結合試験に使用する。五つの所在地項目が一致するとUPS向け住所欄が得られ、同じ住所に未確認の部屋番号を加える、または郵便番号を変えると要確認になる。実配送は行わない。

| 機能 | 合成データで確認すること |
| --- | --- |
| 検証 | 正しい書式・実在する市区町村だけでは架空の部屋番号や配達を証明できない。不正な番号や未対応国も区別する。 |
| 入力補助 | 選んだ国・郵便番号・親候補の配下だけから提案する。連番の途中や別の郵便番号でしか観測していない番地を補わない。 |
| 表記変換 | 未収録の原文は保持し、確認の必要性を返す。全角文字、先頭ゼロ、英数字混在の部屋番号を失わない。 |
| 送り状 | 各欄に収まることと、送付用出力を許可することを別々に確認する。制約内に納まらない建物・部屋を削らず、要確認の場合は送信用の住所欄を返さない。 |

## Address1 の番地・施設判定を測る

リポジトリ直下で実行すると、通常の `validate` が確認した番地・施設の原典IDを期待値と比較する。日・米・中の公的施設と、郵便番号等を入れ替えた反例を含む。

```sh
python -m scripts.evaluate_addresses --examples evaluation/address-ai/address1-public-regression.jsonl --run-address1
```

`input_components` に入力、`expected.entity_id` に「原典ID#原典のレコードID」を記録する。曖昧・競合・未収録は自動確定件数から除く。住戸が未照合でも番地自体の照合は評価できる。国と `setting`（`urban`、`rural`、`island`、省略時は `unspecified`）別に、確定中の正解率、全入力中の確定率、それぞれの95% Wilson信頼区間を出す。住所原文は集計結果に出力しない。

同梱例は原典由来と合成例の回帰確認用。国別の公開目標（番地・施設の確定中の正解率99.5%）は、別途レビューした独立評価セットの件数と信頼区間で判断する。都市の合格のみで農村・島を公開範囲に追加しない。

## 商用の判定に別途必要な証拠

上の試験の合格から、配達成功率や全世界の住所精度は推定できない。本番候補の国・言語・配送サービス（出荷元と配送先を含む）を決めて、次の結果をバージョン付きで記録する。

| 確認項目 | 記録する結果 | 判定の例 |
| --- | --- | --- |
| 住所照合 | 学習・原典と重複しない、利用許諾のある独立データを人手で確認。国・文字体系・番地/部屋の有無別に、採用件数・誤採用件数・保留率を記録。 | 番地・部屋の誤採用はリリースを止めて事例を調査する。十分な件数がない区分は対応済みに含めない。 |
| 入力候補 | 実際の入力途中の接頭辞について上位候補内の正解率、候補ゼロ率、入力時間を測る。候補検索に使った原典と独立した正解を用意する。 | 間違った国・郵便番号の候補、未観測の番地は許容しない。 |
| 翻訳 | 現地語の担当者が地名、行政区画、建物、番地・部屋の維持を対訳で確認。保留率も併記する。 | 配送先を変える訳・識別子の消失はリリースを止める。 |
| 配送業者 | 契約したサービスの仕様版、ルート、文字コード、欄の上限を固定。テスト環境の API 応答と印刷ラベルを、最長住所・多バイト文字・部屋番号を含めて比較する。 | API の受理だけで完了にしない。印刷時の欠落がなく、確認すべき入力は送付工程へ渡らないこと。 |
| 運用 | 索引・モデル・配送プロファイルの版、検証日、ロールバック先、運用環境での同時負荷と応答時間を記録。監視は住所原文を含まない集計値を使う。 | 遅延と誤採用のしきい値を国・用途別に事前合意し、超過時に旧版へ戻せることを確認する。 |

送り状の試験は架空の文字数・バイト数契約で境界を再現する。実際の項目定義は業者と製品ごとに異なる。例：[UPS Shipping API の ShipTo_Address（仕様をコミットで固定）](https://github.com/UPS-API/api-documentation/blob/b4aa85d841ae4ef130b06516ebee17a8578eea1c/Shipping.yaml)、[DHL Express MyDHL SOAP Developer Guide v2.40 の Recipient/Address](https://developer.dhl.com/sites/default/files/2026-02/DHL%20EXPRESS%20-%20MyDHL%20API%20-%20SOAP%20Developer%20Guide%20-%20v2.40_0.pdf)。この文書の記載は配送サービスの利用認定を意味しない。

# 世界の郵便番号を段階的に保存する

250国・地域コードを収集対象とする、原典保存・検索・再検証のレイヤーです。国家数や全国網羅を達成した数とは区別します。

2026-11-24の[取得失敗・保留原典の整理](../docs/plans/source-recovery-20261124.md)で、第3・第4回の保留38判断を漏れなく再分類しました。ブータン・タンザニアの代替取得済み、再取得優先、利用条件・抽出確認待ち、不採用候補を区別しています。今回の復旧OSM索引を郵便番号の公式割当として追加していないため、下記の郵便番号集計は変えていません。

## 段階と完了条件

| 段階 | 保存・追加する内容 | 完了条件 |
|---|---|---|
| 1 基礎保存 | 世界全体の台帳、公開原本、既存日本・台湾の原典 | 原本ハッシュと全行を再検証し、未収集も記録 |
| 2 公式補強 | 日本・中国・台湾、CA/GB/NLの完全桁版を先行し、各国の郵便当局原典へ拡大 | 利用条件・対象範囲・取得版・原典との差分を確認 |
| 3 不足・特殊制度 | 未収録国、大口事業所、私書箱、郵便局、軍・外交、経路限定、制度非採用 | 完全番号・接頭辞・用途限定・制度なし・取得不可を根拠付きで区別 |
| 4 継続管理 | 新版、廃止・変更・統合、復元・差分 | 旧版を残して新しい固定版を追加し、国別の網羅率と最新性を再評価 |

**全世界の現行番号を網羅した状態にはまだ到達していません。** 非公開・利用制限があるデータを公開原本だけで補えない場合も、対象から外さず調査待ちに残します。書式から実在番号を総当たり生成しません。

タンザニアはPDFの旧番号列を除外し、現在番号セルを別の解析方法でも全26原本・全行順で照合しました。原文の6桁 `678010` とセネガルの `159`・`0`・`36` は `source_anomaly` とし、原文のまま保存して標準検索から除外します。桁を埋めたり、隣の旧番号に置換したりしません。折返しのあるKataviの地名は同じセルの原文断片から結合し、Kigomaの表示名はPDFの明示CMapに従って復号します。元の抽出値と位置も保持します。

ブータンの20地域の応答は原文・フォーム条件・バイト数・ハッシュを残し、重複を削除しません。カーボベルデの法令内の例示表、ブータン年次報告の矛盾する地図、公式性を確認できないミャンマーのリポジトリ、公開利用条件に制限があるオマーンのページは取込対象外です。保留理由は [第4回の取込・保留記録](stage4-review.json) に記録しています。

固定URLの29 PDFは原本のまま保存し、取得時にURL・サイズ・SHA-256を照合します。新たな取得先はレビュー済みの公式PDFパスに限定し、リダイレクトや変更された原本は拒否します。変動するHTML・JSON・JavaScriptデータ宣言の3原典は可逆gzipで固定保存し、元バイト列のハッシュも検証します。ページ内のスクリプトは実行しません。

原典観測がある範囲は**125から133国・地域**、調査待ちは117国・地域になりました。合計は**5,336,211観測行**、国＋原文番号4,443,375組です。異表記・履歴・接頭辞・要確認値を含み、現行完全番号の総数ではありません。

ラオスは番号順でページを取得すると境界に重複が生じたため、ID順で取り直しました。採用版は7,781の一意IDを持つ16ページで、各レスポンスの原文・URL・バイト数・ハッシュも保存しています。カンボジアの9ページも照合し、未掲載州を推測補完しません。

モーリシャスの `712547` は18観測にあり、原文のまま `source_anomaly` に分類して標準検索から除外します。別形式の3列原典も標準検索には選びません。空の番号セル1行は明示された `csv:record:545` だけを集計外とし、原本の行自体は保持します。

新原典はgzipで可逆保存し、保存ファイルと展開後の元バイト列の両方についてサイズ・SHA-256を固定しています。HTML・埋込JSON・CSV・法令表・PDFの位置を `source_locator` で追跡し、ページ内のスクリプトを実行しません。変動する公開ページを固定原本へ無断で上書きせず、復元は保存済みのGit版から行います。

[第3回の取込・保留記録](stage3-review.json) に、国別の出典、件数、利用条件、未取得理由を記録しています。取得できなかった国を制度なしと扱わず、規則・桁構造だけから番号を生成しません。

## 番号の種類

| `code_kind` | 扱い |
|---|---|
| `official_full` | 郵便当局の固定原本の完全桁。全国完全性・現行性は別評価 |
| `source_full` | CA/GB/NLの完全桁原典に掲載された値。公式実在性・全国網羅・現行性は別評価 |
| `source_reported` | 原典掲載値。独立した公式確認は未実施 |
| `prefix` | 接頭辞。CA/GB/NLの旧基礎原本、CL/IE/MTと台湾の原典 |
| `aggregated` | 集約番号。中国の今回の原典 |
| `partial` | 一部収録。ブラジルの今回の原典 |
| `partial_or_legacy` | 部分・旧方式。アルゼンチンの今回の原典 |
| `routing_or_unreviewed` | 国内郵便番号と同一視しない特殊・未確認値。今回のAE/HK/MO |
| `source_anomaly` | 原文のまま保存する要確認値。標準検索から除外し、桁を推測補正しない |

通常のGeoNames原本はCA/GB/NLの完全桁版を含みません。CL/CN/IE/MT/AR/BRにも原典上の制約があります。HK/MOの999077/999078は中国本土発の経路に関する値で、国内郵便番号として使えると判断しません。AEの観測も意味を確認するまで保留します。

先頭ゼロ・空白・ハイフン・英字を原文どおり保持します。一つの番号に複数の地名があれば全候補を返し、原典間の異表記を暗黙に同一視しません。国別の制度状況は現在 `unreviewed` とし、未収録から「制度なし」を推定しません。

## コマンド

Python 3.11以降を使います。PDF原典を含む全件再生には固定依存を導入してください。

```bash
python -m pip install -r requirements-postal.txt
python scripts/world_postcodes.py status
python scripts/world_postcodes.py verify
python scripts/world_postcodes.py lookup --country JP --code 0600000 --limit 5
python scripts/world_postcodes.py lookup --country CA --code T0A --include-partial
python scripts/world_postcodes.py lookup --country CA --code 'T0A 0A0'
python scripts/world_postcodes.py lookup --country GB --code 'AL3 8QE'
python scripts/world_postcodes.py lookup --country NL --code '9401 AA'
python scripts/world_postcodes.py lookup --country JP --code 0600000 --include-historical
python scripts/world_postcodes.py lookup --country NA --code 10005
python scripts/world_postcodes.py build
python -m unittest discover -s tests -p 'test_world_postcodes.py' -v
python -m unittest discover -s tests -p 'test_postal_capture.py' -v
python -m unittest discover -s tests -p 'test_postal_full_codes.py' -v
python -m unittest discover -s tests -p 'test_postal_*.py' -v
```

検索は原典の番号文字列との完全一致です。接頭辞は標準検索から除外し、`--include-partial` でも不足桁を補いません。原典掲載値の一致は、現行性・完全住所・配達可能性の検証ではありません。現在は原本走査で、常設API向け索引は後続工程です。

`active_for_lookup: false` の原本は標準検索から除外し、`--include-historical` を指定した場合だけ含めます。これは版の選択であり、選択原本の全行が現在有効であるという保証ではありません。`lookup_source_rows` は原本選択による行数で、部分番号の除外前の集計です。`distinct_codes_by_kind` は種別ごとの一意件数で、異なる種別・原典を単純合算して住所数にはしません。

## 保存と更新

`postal/sources/geonames/20261118/allCountries.zip` に取得原本約20 MBを保存します。国別に同じ内容を重複保存せず、同じ原本から国別に読み出します。日本・台湾は既存の保存原本を参照します。

第2段階では `postal/sources/geonames/20261118-full/` の3原本と `postal/sources/japanpost/20261030/` の2原本を追加しています。既存の原本は保持します。取得先はGeoNamesの郵便番号配布パスと、日本郵便の通常・事業所原本の配布パスに限定し、同一ホストの別パスへのリダイレクトも受け入れません。

`capture` は固定URL・バイト数・SHA-256を満たす原本だけ保存します。配布元が新版へ変われば停止し、既存原本を上書きしません。新しい取得は保存先・ハッシュ・対象範囲をレビューして追加します。

GitHubの `codex/postal-*` 作業ブランチでは [原本保存](../.github/workflows/postal-capture.yml) が取得・全行検査後、原本と台帳だけを同じブランチへコミットします。mainへの直接書込み・定期実行は行いません。[PR品質検査](../.github/workflows/postal-quality.yml) は保存済み原本を再検証します。
